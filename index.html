The table

Everything lives in one table, spotify. Each row is a track, joined to its matching YouTube video.

GroupColumnsWhat they hold
Track infoartist track album album_typeWho made the track and how it was released, such as a single or an album.
Audio featuresdanceability energy loudness speechiness acousticness instrumentalness liveness valence tempo duration_minSpotify’s measures of how a track sounds. Most run from 0 to 1. Loudness is in decibels, tempo in beats per minute and duration in minutes.
YouTube statstitle channel views likes comments licensed official_videoThe matching video. licensed and official_video are stored as text, not true or false values.
Playsstream most_playedon energy_livenessSpotify stream count, the platform with more plays, and a derived energy and liveness value.

Things to check before you run these

  • Query 2 is labelled “more than 1 billion streams” but filters on stream > 1000000. Use 1000000000 to match the label.
  • Query 4 writes sum (comments) with a space. MySQL rejects that by default, so write sum(comments).
  • Queries 4 and 9 compare to 'True'. String comparison in MySQL ignores case, but check how the CSV stores the values.
  • Query 9 compares views > likes. Nearly every video has more views than likes, so this returns almost everything.
  • Query 14 relies on most_playedon being exactly youtube or spotify.
